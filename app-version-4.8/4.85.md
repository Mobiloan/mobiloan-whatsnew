# 4.85 Release notes

## 4.85.00 – Evaluation Counter-Offer, Bonus Income & Branch Controls

_Released: 2026-07-21_

4.85.00 is a consolidated release for your branches covering everything shipped since **4.84.05** (15 July 2026). Headline additions are **Evaluation Counter-Offer** (revise capital without declining), structured **Expected Bonus Income** on salary-path affordability, **pin important client notes**, **pin Trust Center tickets**, and an **origination concurrency warning** when another operator is already originating the same client. This release also fixes employer discount double-application, SMR last-day staging gaps, Profit & Loss month selection after custom-date reports, Compuscan dispute reason labels, and several origination and payment-allocation reliability issues.

### 🚀 New Features

#### Evaluation Counter-Offer — revise capital without declining

**What changed:** Evaluators with the **Evaluation Counter Offer** role right can offer a **lower capital** on a **Signed** loan already in evaluation — without declining and forcing a re-application (which previously hurt decline-rate metrics).

**How to use it:**

1. Open the loan in evaluation (status **Signed**)
2. Choose **Counter offer** from Evaluation Outcome, or from the evaluation button group
3. Enter revised capital (less than the current amount) and a reason
4. At payout, the client must explicitly accept (or decline) the revised terms and re-sign; declining does **not** auto-decline the loan

#### Expected bonus-month income (13th cheque / contractual bonus)

**What changed:** Salary-path affordability can now capture **Expected Bonus Income** as a structured field — no more parking bonus money under informal income and notes.

**How to use it:**

1. Administrator: enable **Allow expected bonus-month income** on the category (Config → Category → Affordability); optional maximum defaults to net salary when unset
2. Grant evaluators **Expected bonus-month income captured on affordability** under Authorise General Client Warnings
3. Branches capture bonus on the affordability screen — not as informal income

#### Pin important client notes

**What changed:** Operators with **client maintenance** rights can **pin** important notes so they stay above newer system/hold notes on Client Menu → Notes, origination previews, and Client Contact.

**How to use it:**

1. Open the client → **Notes**
2. From the note action menu choose **Pin note** (or use **Pin this note** inside the note)
3. Pinned notes sort first with a pin icon and **Pinned** badge; choose **Unpin note** to restore normal date order

{% hint style="info" %}
**Why it matters:** Critical context (fraud warnings, special arrangements) stays visible during evaluation instead of being buried under automated hold notes.

**Who is affected:** Operators with client maintenance rights; all viewers benefit when reading pinned notes.
{% endhint %}

#### Pin Trust Center tickets (Zendesk & Mobidesk)

**What changed:** In Trust Center help desk, operators can **pin** frequently used Zendesk or Mobidesk tickets. Pinned tickets sort first with a star icon; pin state is per operator and survives logout. Mobidesk conversations open in a dialog on the ticket list, and **Continue on WhatsApp** resolves the support number more reliably.

#### Origination concurrency warning

**What changed:** When another operator has started a **New Loan** for the same client within the last hour, Mobiloan warns before navigation. The lock clears when the loan is successfully signed. Operators can still proceed with OK if needed (advisory lock).

<div align="left"><figure><img src="../.gitbook/assets/origination-concurrency-warning.png" alt="Origination concurrency warning" width="375"><figcaption></figcaption></figure></div>

{% hint style="info" %}
**Why it matters:** Reduces duplicate origination work on the same client across branches.

**Who is affected:** All originators.
{% endhint %}

### 🛠️ Improvements & Fixes

* **Employer discount no longer applied twice** — when a product has both an employer promo % and a **max fees %**, the calculated discount now matches the configured rule (e.g. 10% stays ~10%, not ~19%). The quotation repayment schedule shows **Discount percent** and a **Discount {rate}** column heading when a promo applies. Loans already paid out with the old compounded discount are **not** rewritten — only new quotations / originations after deploy.
* **Employer name no longer clears while typing “Ta…”** — names such as Tambo / Taung can be typed normally; full SACRRA cleanup still runs on save.
* **Compuscan Approved Dispute Reasons** — two new options: **Account Restructured or Settled** and **Account Transferred to New Agreement**. Enable per category under Config → Category → Credit Check → Approved Dispute Reasons.
* **Standard SMR / Advanced Summary** — if month-end staging data is stale (e.g. report run before the 07:00 refresh), Mobiloan detects the gap and rebuilds staging before generating the PDF, so the last calendar day's payouts are not missing.
* **Profit & Loss** — no longer crashes after using Custom dates on another advanced report; month preselect defaults safely to **This month**.
* **Failed Payment Allocation alert emails** no longer show **Promissory ID: undefined** on the Local CRS pre-create path.
* **TFS bulk screening** reports an incomplete run when the Excel proof fails to save; **Principa** instalment-to-income ratios include expected bonus income when captured.

### Setup & admin checklist

| Decision | Where |
| --- | --- |
| Who may counter-offer in evaluation | Role → Evaluation → **Evaluation Counter Offer** |
| Who may approve loans with bonus income | Role → Authorise General Client Warnings → **Expected bonus-month income…** |
| Which categories allow bonus income | Category → Affordability → **Allow expected bonus-month income** (+ optional max) |
| New Compuscan dispute reasons | Category → Credit Check → tick the two new Approved Dispute Reasons |

Branches need no local install — the release is applied centrally. Force-close and reopen the app after deploy so schema changes (pins, bonus, counter-offer, lock) sync cleanly.
